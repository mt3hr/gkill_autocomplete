# テストと検証

## 1. 実行

```
npm test                # 資料の検査 → Go → 確認画面
npm run verify_docs     # 資料の件数とリンク
npm run test_go         # Go のテスト
npm run test_client     # 確認画面のテスト
```

Windows で並列のプロセスが多すぎると、無関係な失敗が出ることがあります。その場合は
`cd src/autocomplete && go test -p 2 ./...` にしてください。

## 2. 件数

**Go のテスト宣言 157件（15ファイル）**、Go のソースは 42ファイルです。

このうち2件は実物の LLM を相手にする検査で、既定では走りません。LLM は同じ入力でも
必ずしも同じ答えを返さないので、ふだんのテストに混ぜると理由なく落ちるようになるためです。

```
GKILL_AUTOCOMPLETE_LLM_INTEGRATION=1 \
GKILL_AUTOCOMPLETE_LLM_TEXT_MODEL=<テキストのモデル> \
GKILL_AUTOCOMPLETE_LLM_VISION_MODEL=<視覚のモデル> \
  go test ./internal/classify/ -run Integration -v
```

見るのは**答えの中身ではなく、往復が成立すること**です。応答が解釈でき、候補の外へ出ず、
確信度が範囲に収まっていることを確かめます。利用者の写真は使わず、その場で作った画像を渡します。

視覚のモデルは初回の読み込みに時間がかかります。時間切れになる場合は、先に一度呼んで
常駐させてから走らせてください。

数値はトップレベルのテスト宣言の静的な数であり、実行時のケース数とは一致しません。
表引きのテストは1つの宣言から複数のケースを展開します。

この数値は `npm run verify_docs -- --list` が算出するものと同じ定義で、`verify_docs` が
実測と突き合わせます。

## 3. 何を守っているか

テストは「壊れると困ること」に絞って書いています。型やコンパイラが保証済みのことは書きません。

### 個人情報

| 守っていること | 場所 |
| --- | --- |
| 外部の LLM 接続先で起動を拒否する | `internal/config` |
| 設定に資格情報を書く項目が存在しない | `internal/config` |
| 設定ファイルに秘密が書き出されない | `internal/config` |
| 既定値に実在のタグ名・リポジトリ名が入っていない | `internal/config` |
| LLM へ記録のID・リポジトリ名・ファイル名を渡さない | `internal/classify` |
| 写真の中継が一覧に無いファイルを読ませない | `internal/websrv` |
| 未ログインでは記録に触れる口が全て塞がる | `internal/websrv` |
| 未ログインへの応答に記録の中身が混ざらない | `internal/websrv` |
| ログイン試行が15分5回で止まる | `internal/websrv` |

### 認証

| 守っていること | 場所 |
| --- | --- |
| 無効なアカウントで入れない | `internal/gkillauth`、`internal/websrv` |
| パスワード未設定で入れない（fail-closed） | `internal/gkillauth`、`internal/websrv` |
| リセットトークンが残っていると期限に関わらず入れない | `internal/gkillauth`、`internal/websrv` |
| 平文のパスワードを送っても通らない | `internal/gkillauth` |
| 弾いた理由が応答に漏れない | `internal/websrv` |
| **旧スキーマの `account.db` を開かずに止まる** | `internal/gkillauth` |
| `/api/login` を一度も叩かない | `internal/gkillclient` |
| 利用者を指定しないと起動しない | `cmd/gkill_autocomplete` |

### 利用者ごとの分離

**このアプリで一番まずい壊れ方**（他人の記録の本文が画面に出る）を防ぐところ。

| 守っていること | 場所 |
| --- | --- |
| 他人の提案が一覧にも件数にも出ない | `internal/store`、`internal/websrv` |
| 同じ記録を2人が別々に判定できる | `internal/store` |
| 掃除が他人の提案を消さない | `internal/store` |
| 利用者IDが空のまま保存先を触れない | `internal/store` |
| 解析対象でない利用者は承認も解析もできない | `internal/websrv` |
| 写真の索引が利用者ごとに分かれている | `internal/websrv` |

### 判定の正しさ

| 守っていること | 場所 |
| --- | --- |
| 提案0個が正常な結果として扱われる | `internal/suggest` |
| 逐語一致で複数のタグを提案できる | `internal/suggest` |
| 上の段階で決まったら LLM を呼ばない | `internal/suggest` |
| 候補に無いタグを LLM が作っても捨てる | `internal/classify` |
| 機械が付けたタグを候補にしない | `internal/suggest`、`internal/app` |
| 学習の文脈が端末の違いでばらけない | `internal/suggest` |

### 消えては困るもの

| 守っていること | 場所 |
| --- | --- |
| 却下した提案が解析し直しても復活しない | `internal/store`、`internal/app` |
| タグ不要にした記録に新しい提案が出ない | `internal/store`、`internal/websrv` |
| 派生データを掃除しても判定が残る | `internal/store` |
| 開き直しても判定が残る | `internal/store` |
| 識別子が実行のたびに変わらない | `internal/ids` |

### gkill との通信

| 守っていること | 場所 |
| --- | --- |
| セッションを呼ぶたびに作り直さない | `internal/gkillclient` |
| セッション期限切れで取り直す | `internal/gkillclient` |
| 取り直しは1回だけ | `internal/gkillclient` |
| 成功時の `errors: null` を失敗にしない | `internal/gkillclient` |
| 既存タグのエラーを失敗にしない | `internal/gkillclient` |
| タグに記録の時刻を入れる | `internal/gkillclient`、`internal/websrv` |
| 上限を超えるサムネイル指定を送らない | `internal/gkillclient` |
| 未設定の検索条件を送らない | `internal/gkillclient` |

### 黙って質を落とさない

| 守っていること | 場所 |
| --- | --- |
| 取得が上限で打ち切られたら警告する | `internal/app` |
| 見本写真を設定した枚数より多く送らない | `internal/classify` |
| 文脈長が足りないとき直し方を出す | `internal/llm` |

写真は1枚で千数百トークンになるので、見本を数枚添えるだけで LLM の文脈長を超えます。
また取得の打ち切りは「正常終了」に見えてしまいます。どちらも**気づけないまま結果が悪くなる**
たちの問題なので、テストで固定しています。

最後の1つは見落としやすい罠です。gkill の検索条件は**空の配列と未設定で意味が変わります**。
未設定のつもりで空の配列を送ると「該当0件」の指定になり、検索結果が黙って空になります。

## 4. 本番を汚さない

### 読み取りと書き込みを分ける

- **記録の取得とサムネイルの取得は読み取り**です。本番の gkill に向けて構いません
- **タグの書き込みは確認画面から承認したときだけ**起きます。解析（`--once`）は書き込みません

書き込みを試したい場合は、別のポートで動かした gkill か、使い捨ての利用者を用意してください。

### `account.db` を壊さない

**アカウントDBを DAO で開く前に、必ずスキーマ版を確かめること。** 旧版を開くと
gkill 側が自動移行を走らせ、**全アカウントのパスワードが無効化されて
リセットトークンが再発行されます**。テストで本番の設定ディレクトリを指さないでください。

`internal/gkillauth` と `internal/websrv` のテストは、gkill の DAO を使って
一時ディレクトリに新しい `account.db` を作ります。本番のものは触りません。
**照合は本番と同じ Argon2id の経路を通る**ので、模造品にはしていません。
そのぶん遅い（1件あたり数十ミリ秒）のは仕様です。

### 保存先を分ける

```
GKILL_AUTOCOMPLETE_HOME=/tmp/gkill_autocomplete_test gkill_autocomplete --user <利用者ID> --once
```

ふだんの判定を汚さずに試せます。

## 5. 精度を測る

判定がどれくらい当たるかは、**既にタグを付け終えた過去の期間**で測ります。

```
gkill_autocomplete benchmark --user <利用者ID> --from 2020-06-01 --to 2020-06-08
```

**保存先にも gkill にも一切書き込みません。** 読み取りだけです。

### 学習と計測を分ける

**学習には計測期間より前の記録だけを使います。** 同じ期間を学習に混ぜると、逐語一致が
自分自身を引き当てて満点が出てしまい、実力とかけ離れた数字になります。

この分離はテストで固定してあります（`TestBenchmarkDoesNotLearnFromEvaluationPeriod`）。

近傍の記録は計測期間のものも使います。近傍から見るのは見出しと本文だけで、タグは見ないので
答えが漏れることはありません。

### 読み方

| 指標 | 意味 |
| --- | --- |
| 適合率 | 提案したもののうち当たっていた割合。低いと確認画面で却下する手間が増える |
| 再現率 | 実際に付いていたタグのうち提案できた割合。低いと手作業が残る |
| 完全一致 | 提案した集合が実際のタグの集合とぴったり一致した記録の数 |
| タグ不要を正しく黙った | タグの無い記録に何も提案しなかった数 |
| タグ不要なのに提案した | 余計な提案。**ここが多いと日々の手間が増える** |

**タグを付けていない記録も正解に含めています。**「提案しないのが正解」というケースを外すと、
実力を過大に見積もることになります。

閾値の調整は、外れを減らすことと取りこぼしを減らすことの釣り合いで決めます。
このツールは提案するだけなので、取りこぼしのほうが害は小さいと考えています。

## 6. LLM を含む検証

LLM は同じ入力に対して必ずしも同じ答えを返しません。自動テストでは**偽の LLM に差し替えます**
（`Classifier` インターフェースがその境目です）。

実物の LLM を含めた確認は手で行い、次を見ます。

- 見た目が似ていて中身が違うものを取り違えていないか
- 「どれも当てはまらない」をちゃんと返すか
- 候補に無い名前を作っていないか

## 7. 資料の検査

`npm run verify_docs` は次を見ます。

| 検査 | 失敗の扱い |
| --- | --- |
| 件数が実測と合っているか | エラー |
| 資料どうしのリンクが切れていないか | エラー |
| Mermaid のブロックが図として成立しているか | エラー |
| 資料が参照しているパスが実在するか | 警告 |

正しい数値は `npm run verify_docs -- --list` で引けます。手で数えないでください。
