# 画面遷移図

確認画面は**1ページだけ**です。ルータもありません。出し分けは状態で行います。

## 1. 全体

```mermaid
stateDiagram-v2
    [*] --> 確認中 : ページを開く

    確認中 --> ログイン画面 : 未ログイン
    確認中 --> 提案画面 : ログイン済み

    ログイン画面 --> 提案画面 : 資格情報が通る
    ログイン画面 --> ログイン画面 : 資格情報が違う<br/>(その場に留まる)

    提案画面 --> ログイン画面 : ログアウト
    提案画面 --> ログイン画面 : 期限切れ(401 を受けた)

    note left of 確認中
        ログイン状態が分かるまで
        どちらも描かない
        先に本体を描くと、未ログインでも
        中身があるように見えてしまう
    end note
```

`App.vue` が `is_checked` / `is_authenticated` の2つで出し分けます。
**`is_checked` が偽の間は何も描きません。**

## 2. 提案画面の中の状態

ページ遷移はありません。同じ画面が状態で姿を変えます。

```mermaid
stateDiagram-v2
    [*] --> 読み込み中 : 開いた直後

    読み込み中 --> 対象外 : is_analyzable が偽
    読み込み中 --> 空 : 提案が0件
    読み込み中 --> 判定中 : 提案がある

    判定中 --> 判定中 : j / k で前後へ
    判定中 --> 判定中 : 確定して次の記録へ
    判定中 --> 空 : 最後の1件を確定した

    空 --> 読み込み中 : 解析する / 読み直す
    判定中 --> 読み込み中 : 読み直す

    対象外 --> 対象外 : 解析ボタンは押せない

    note right of 対象外
        起動時に --user へ
        渡されていないアカウント
        「提案0件」と区別して出す
    end note
```

**「空」と「対象外」を分けているのが要点です。** どちらも提案は出ませんが、
利用者がやるべきことが違います（前者は解析する、後者は起動しなおす）。

## 3. 操作と遷移

| 操作 | どこから | 何が起きるか |
| --- | --- | --- |
| 入る | ログイン画面 | 照合が通れば提案画面へ。**通らなければ留まる** |
| `j` / `↓` | 判定中 | 次の記録へ。選択は解除される |
| `k` / `↑` | 判定中 | 前の記録へ。選択は解除される |
| `1`〜`9` | 判定中 | その番号の候補タグを選ぶ／外す |
| `Enter` | 判定中 | 確定。**何も選んでいなければタグ不要** |
| `x` / `Delete` | 判定中 | タグ不要として確定 |
| 更新ボタン | どこでも | 解析を1回走らせ、終わったら読み直す |
| 読み直しボタン | どこでも | 一覧だけを取り直す |
| テーマボタン | どこでも | 星と雪を切り替える。クッキーに覚える |
| ログアウト | どこでも | ログイン画面へ |

キーボードは**文字を打っている最中には反応しません**（`input` / `textarea` /
`contenteditable` に焦点があるとき、および修飾キーが押されているとき）。
自分でタグを足す欄があるためです。

## 4. 確定したときの見え方

```mermaid
sequenceDiagram
    participant User as 利用者
    participant Page as 提案画面
    participant Srv as サーバ

    User->>Page: 確定
    Note over Page: 押した瞬間に一覧から外す
    Page->>Srv: POST /api/decide

    alt 成功
        Srv-->>Page: 承認/却下の件数
        Page->>User: 通知を出す(2.5秒で消える)
    else 失敗
        Srv-->>Page: エラー
        Note over Page: 元の位置へ戻す
        Page->>User: 赤い通知(消えない)
    else 期限切れ
        Srv-->>Page: 401
        Page->>User: ログイン画面へ
    end
```

**先に外して、失敗したら戻します。** 待たせないためです。
同じ記録への二重確定は `in_flight` で防ぎます。

## 5. ログインできない場合の分かれ道

```mermaid
flowchart TD
    Start([入るを押した]) --> Secure{crypto.subtle が使える?}
    Secure -->|いいえ| ErrCtx[「https:// か localhost で開いてください」<br/>平文は送らない]
    Secure -->|はい| Hash[パスワードを SHA-256 にする]

    Hash --> Post[POST /api/login]
    Post --> Result{応答}

    Result -->|200| Refresh[セッションを聞き直して提案画面へ]
    Result -->|401| Same[「利用者IDかパスワードが違います」<br/>その場に留まる]
    Result -->|429| Wait[「15分ほど待ってください」]
    Result -->|500| Fail[「アカウントを確認できませんでした」]

    style ErrCtx fill:#fdd,stroke:#333
```

**平文へ落ちる道はありません。** 安全なコンテキストで開けないときは、
パスワードを送らずに理由を出して止まります。

401 の文面は**どの理由でも同じ**です（アカウントが無い・無効・リセット中・
パスワード違い）。アカウントの存在や状態を外から探れないようにするためです。

## 6. PWA としての入り口

```mermaid
stateDiagram-v2
    [*] --> ブラウザ : URL を開く
    ブラウザ --> ホーム画面 : 「アプリをインストール」

    ホーム画面 --> 単体表示 : アイコンから開く
    単体表示 --> ログイン画面 : 通常と同じ

    note right of ブラウザ
        証明書が信頼されていないと
        インストールできない
        (Service Worker が動かないため)
    end note
```

単体表示（`display: standalone`）ではブラウザの枠が消えますが、
画面の中身と遷移は同じです。

**オフラインでは画面の器だけが開き、提案は出ません。** 記録の中身を
Service Worker に溜めない設計なので、これは意図した動きです。
