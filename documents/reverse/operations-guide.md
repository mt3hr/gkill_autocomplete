# 導入と運用

## 1. 置き場

設定とデータベースは `$GKILL_AUTOCOMPLETE_HOME`
（既定 `$HOME/gkill_autocomplete`）に作られます。**リポジトリの中には作りません。**

| ファイル | 内容 | 失ったら |
| --- | --- | --- |
| `config.json` | 設定。実在のタグ名とリポジトリ名が入る | `init` で作り直せる。手で調整した分は戻らない |
| `gkill_autocomplete.db` | 提案と**人間の判定** | **判定が戻らない**。却下したはずの提案が全部復活する |

いずれも所有者だけが読める権限で作ります。

**資格情報を保存するファイルはありません。** 認証は gkill 自身の設定ディレクトリを
見て行うので、パスワードもそのハッシュも、発行済みセッションも持ちません。

## 2. 認証の仕組み

このツールは gkill と**同じ端末で動かすこと**を前提にしています。
そのことがそのまま権限の根拠になります。

```
$GKILL_HOME/configs/
├── account.db        … 確認画面のログインを照合する
├── account_state.db  … gkill を叩くためのセッションを直接発行する
└── server_config.db  … TLS 証明書の場所と gkill の宛先を読む
```

### 2.1 コマンドラインは資格情報を受け取らない

```
gkill_autocomplete --user sample_user
```

渡すのは利用者IDだけです。gkill の API を叩くためのセッションは
`account_state.db` へ直接書いて発行します。gkill 自身の `auto_tag` や
`update_cache` と同じ手口で、**信頼の根拠は「同じ端末で設定ディレクトリに
書けること」**です。

`--user` は繰り返せます。指定した人ぶんだけ解析が回り、保存先の行も人ごとに分かれます。

```
gkill_autocomplete --user sample_user --user sample_user_all
```

発行したセッションは終了時に消します。有効期間は1週間で、使っている間は
自動で取り直します。**gkill の `/api/login` は一度も叩きません。**

期限を長く取っているのは、確認画面を何日も上げたままにするためです。
そのぶん gkill の `account_state.db` に長寿命の行が置かれるので、
強制終了させたときは期限まで残ります。

### 2.2 確認画面のログイン

gkill のアカウントでログインします。**有効なアカウントなら誰でも入れます。**

照合は手元の `account.db` に対して行い、gkill の `/api/login` は叩きません。
叩くと gkill 側のログイン回数（IP毎・15分に10回）を消費してしまい、
この画面が総当たりを受けたときに**利用者自身が gkill へ入れなくなる**ためです。

| 決まり | 理由 |
| --- | --- |
| 弾く順序は gkill と同じ | 回数制限 → アカウントの有無 → 有効か → リセット中か → パスワード |
| リセットトークンが残っていると入れない | 期限の内外に関わらず。gkill と同じ |
| パスワード未設定は常に不一致 | fail-closed。空パスワードで入れない |
| どこで弾いたかは伝えない | アカウントの存在や状態を外から探れないように |
| ログイン試行は15分に5回まで | gkill 側の回数は消費しないが、総当たり自体は止める |

**見えるのは自分の提案だけです。** `--user` に渡されていないアカウントでも
ログインはできますが、提案は空になり、解析も承認もできません。

パスワードはブラウザの中で SHA-256 にしてから送ります（gkill の画面と同じ形）。
平文はブラウザから出ません。

### 2.3 アカウントDBのスキーマ

起動時に `account.db` のスキーマ版を読み、現行版でなければ**何もせずに止まります**。

これは飾りの検査ではありません。gkill のアカウントDAOは旧スキーマのDBを開いた瞬間に
自動移行を走らせ、**全アカウントのパスワードを無効化してリセットトークンを再発行します**。
このツールがうっかり先に開くと、gkill にログインできなくなります。
移行は gkill 自身にやらせるべきなので、こちらは触りません。

止まった場合は、先に gkill を起動して移行を済ませてください。

## 3. TLS

gkill が TLS を使っている場合、確認画面も**同じ証明書**で待ち受けます。
証明書の場所は `server_config.db` から読みます。専用の証明書を作らないのは、
利用者に証明書をもう1枚信頼させないためです。

gkill 側が TLS を切っている構成では、こちらも平文で開きます（食い違わせないため）。

### 3.1 その証明書がどの名前を保証しているか

**ここが躓きどころです。** 証明書は「どの名前で来た接続を保証するか」を持っており、
そこに載っていない名前で開くとブラウザが止めます。自己署名かどうかとは別の話で、
証明書を端末に入れても解決しません。

いま使われている証明書が何を保証しているかは、次で確かめられます。

```powershell
$cert = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2("$env:USERPROFILE\gkill\tls\cert.cer")
($cert.Extensions | Where-Object { $_.Oid.Value -eq '2.5.29.17' }).Format($false)
```

出てきた名前で開いてください。`localhost` が載っていなければ、
同じ端末からでも `https://localhost:9797/` は警告になります。

### 3.2 警告を消す

| 警告の内容 | 意味 | 消し方 |
| --- | --- | --- |
| 発行元が信頼されていない | 自己署名なので当然 | 証明書を端末の信頼済みに入れる |
| 名前が一致しない | その名前が証明書に載っていない | **載っている名前で開く**。証明書を入れても消えない |

別の端末（スマートフォンなど）から使う場合は、`cert.cer` をその端末へ持っていき、
信頼済みの証明書として入れてください。

## 4. ホーム画面に入れる（PWA）

確認画面は PWA です。ブラウザのメニューから「ホーム画面に追加」「アプリをインストール」を
選ぶと、単体のアプリのように開けます。

**インストールには証明書が信頼されている必要があります。** ブラウザは警告を出した
接続では Service Worker を動かさないので、3.2 の手順を先に済ませてください。

### 何をキャッシュするか

| 対象 | 扱い |
| --- | --- |
| 画面そのもの（JS / CSS / フォント / アイコン） | キャッシュする |
| 提案・記録の中身・写真（`/api` と `/thumb`） | **決してキャッシュしない** |

記録の中身を溜めると、ログアウトしても端末に残り、端末を共有していれば
他の人からも読めてしまいます。溜めてよいのは画面の器だけです。

そのため**オフラインでは画面が開くだけで、中身は出ません**。これは意図した動きです。

## 5. 初回の設定

### 5.1 設定ファイルの生成

```
gkill_autocomplete init --user sample_user
```

稼働中の gkill を読んで、使い方に合わせた設定を作ります。**既にファイルがある場合は上書きしません。**

生成された設定を開いて、対象にする範囲が意図どおりか確かめてください。
自動選択は「2種類以上のタグを使い分けており、タグを付けない記録も混じっている場所」を選びます。

### 5.2 接続先

**通常は何も書かなくて構いません。** `gkill.base_url` を空にしておくと、
gkill 自身のサーバ設定（TLS の有無と待ち受けポート）から組み立てます。

手で書くと、gkill 側の設定を変えたときに食い違って繋がらなくなります。
取り違えた場合は、直し方を添えたエラーが出ます。

### 5.3 LLM

**`init` が接続先に問い合わせて、使えるモデルを設定に書き込みます。** 名前から
「写真を扱えそうなもの」と「本文向きのもの」を選び、選んだ結果を画面に出します。
名前だけで判断しているので、違っていれば設定を直してください。

LLM が動いていなくても `init` は失敗しません。その場合はモデルの欄が空のままになるので、
あとから `llm.text_model` と `llm.vision_model` に書き足してください。

**接続先はループバックでなければ起動を拒否します。** クラウドの LLM を使う設定項目はありません。

モデルを設定しない場合、LLM の段階は飛ばされ、逐語一致と近傍による判定だけで動きます。
写真の判定には視覚のモデルが必要です。

使えるモデルは次でも確かめられます（`init` が見ているのと同じ口です）。

```
curl http://127.0.0.1:11434/v1/models
```

### 5.4 写真の判定が遅いとき

**写真の判定は、視覚エンコーダ（mmproj / CLIP）が GPU に載っているかどうかで所要時間が桁で変わります。**
本文の判定が速いのに写真だけが遅いなら、まずここを疑ってください。

見分け方は3つあります。

| 見るもの | GPU に載っている | CPU で動いている |
| --- | --- | --- |
| LLM サーバのログ | `CLIP using CUDA0 backend` | `CLIP using CPU backend` |
| 判定中の GPU 使用率 | 高い | ほぼ0のまま。代わりに CPU が数コア張り付く |
| 1件あたり | 数秒 | 数分 |

**LLM サーバによっては mmproj を CPU に置く判断を自分で下し、切り替える手段を持ちません。**
その場合は llama.cpp の `llama-server` を直接起動すると、こちらでフラグを決められます。

- `--mmproj` を付け、**`--no-mmproj-offload` は付けない**
- `--n-gpu-layers` を層数以上にする
- 視覚モデル1つで本文の判定も賄えるので、`text_model` と `vision_model` を同じ値にすれば
  サーバは1つで済みます（LLM サーバが1モデルしか持たない場合、`model` フィールドは無視されます）

起動でありがちな失敗が1つあります。**`GGML_BACKEND_PATH` はディレクトリではなく
バックエンド DLL のフルパスを渡します。** ディレクトリを渡すと警告も出さずに CPU だけで起動し、
モデルの読み込みが終わるまで気づけません。次のコマンドはモデルを読まずに一瞬で返るので、
**起動スクリプトの中で先に確かめてください**。

```
llama-server --list-devices
```

GPU が列挙されなければ、そのまま起動しても意味がありません。

**VRAM は LLM サーバどうしで分け合えません。** 別の LLM 実行環境（チャット UI など）を
同じ GPU で使っているなら、どちらか一方を止める運用になります。

## 6. ふだんの使い方

```
gkill_autocomplete --user sample_user --once    解析して提案を作る
gkill_autocomplete --user sample_user           確認画面を開く
```

解析は時間がかかるので、定期実行に回して朝まとめて確認する使い方を想定しています。
Windows ならタスクスケジューラ、Linux なら cron や systemd timer に `--once` を登録します。
**資格情報を渡さずに済むので、定期実行に秘密を置く必要がありません。**

確認画面は既定で `127.0.0.1:9797` に開きます。`server.listen` を変えれば外にも開けます。

### 確認画面の操作

| キー | 動作 |
| --- | --- |
| `j` / `k` | 次へ / 前へ |
| `1`〜`9` | 候補タグを選ぶ（複数選べます） |
| `Enter` | 確定。**何も選ばなければ「タグ不要」** |
| `x` | タグ不要 |

記録の一定割合は元々タグが要りません。`x` が最短の操作になるようにしてあります。

一度「タグ不要」にした記録は二度と提案されません。

## 7. 設定の調整

### 提案が多すぎる・外れが多い

| 調整 | 効果 |
| --- | --- |
| `scoring.threshold` を上げる | 確信の低い提案が出なくなる |
| `candidates.min_examples` を上げる | 実績の少ないタグが候補から外れる |
| `exclude.tag_patterns` に足す | 特定のタグを候補から外す |
| `rules` に `never_suggest` を書く | 条件付きで特定のタグを止める |

### 提案が出ない

| 調整 | 効果 |
| --- | --- |
| `scoring.threshold` を下げる | 確信の低い提案も出る |
| `candidates.min_examples` を下げる | 実績の少ないタグも候補になる |
| `scope.learn_days` を伸ばす | 学習に使う履歴が増える |
| `scope.rep_prefixes` を確かめる | 対象の範囲が狭すぎないか |

### 手で決め打ちする

`rules` に書きます。設定だけで挙動が変わり、コードを直す必要はありません。
書き方は `config.example.json` を参照してください。

## 8. 解析をやり直す

```
gkill_autocomplete reset --user sample_user
```

提案は派生データなので、消して作り直せます。**人間の判定は消えません。**
消えるのは指定した利用者のぶんだけです。

やり直すと、逐語一致で決まっていた記録も含めて全部を判定し直します。LLM を使う設定では
時間がかかります。

## 9. 困ったとき

| 症状 | 原因と対処 |
| --- | --- |
| 利用者を指定しろと言われる | `--user <利用者ID>` を渡す。パスワードは要らない |
| スキーマ版が違うと言われる | 先に gkill を起動して移行を済ませる。**こちらでは移行しない** |
| 有効なデバイスが無いと言われる | gkill の設定でこの端末が有効になっていない |
| 証明書が見つからない | gkill の設定画面で証明書を作り直す |
| ブラウザが名前の不一致と言う | 証明書に載っている名前で開く（3.1 参照） |
| 起動が拒否される | LLM の接続先がループバックでない。仕様なので設定を直す |
| gkill が HTTP 403 | gkill 側のローカル限定アクセス。同じ端末から実行する |
| ログインが通らない | 15分に5回の制限。**gkill 側の回数は減っていない**ので、gkill には入れる |
| 提案が空でログアウトもできる | そのアカウントが `--user` に渡されていない。画面にその旨が出る |
| 承認したのにタグが付かない | 同じ識別子のタグが既にある。過去に付けて手で消した記録では意図した挙動 |
| 同じ記録が何度も出る | 判定が保存できていない。保存先の書き込み権限を確かめる |
| 写真が出ない | gkill 側でファイルが消えているか、一覧を開き直していない |
| 提案が全部同じタグ | 機械が付けたタグが候補に混ざっている。`exclude.tag_patterns` に足す |
| 進捗は進むのに提案が増えない | 判定が失敗して飛ばされ続けている。失敗は理由ごとに1回だけログに出るので、`解析を開始します` の直後まで遡る。理由が「LLM の応答を解釈できない」なら 5.3 と 7 を参照 |
| 判定する記録が極端に少ない | 対象の記録が既に判定済み。`EVALUATION` に印が残っている（8章）。付け直すなら `reset` |
| 写真の判定だけ数分かかる | 視覚エンコーダが CPU で動いている。5.4 を参照 |

## 10. バックアップ

**`gkill_autocomplete.db` だけは失うと戻りません。** 承認・却下・タグ不要の判定が入っており、
これらは再生成できません。

`config.json` は `init` で作り直せますが、手で調整した分は戻りません。

## 11. 個人情報について

- 記録の本文と写真が出るのは、**手元のブラウザとローカルの LLM だけ**です
- ログには件数と所要時間しか出ません
- 写真は gkill から取り寄せて中継するだけで、ディスクには残しません
- Service Worker も記録の中身は溜めません（4章）
- 通信先は gkill とローカル LLM の2つだけです。テレメトリも更新チェックもありません
- **資格情報を保存するファイルがありません**

リポジトリを公開する場合、`config.json` と `*.db` が含まれていないことを確かめてください
（`.gitignore` で除外していますが、置き場を変えた場合は自分で確かめる必要があります）。
