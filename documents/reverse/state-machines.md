# ステートマシン図

状態を持つものは3つです。**提案**、**記録**、**セッション**。

## 1. 提案の状態

提案1件は「未判定」から始まり、人が触ると二度と戻りません。

```mermaid
stateDiagram-v2
    [*] --> 未判定 : 解析が提案を作る

    未判定 --> 承認済 : 選んで確定
    未判定 --> 却下済 : 選ばずに確定<br/>(同じ記録の他の提案)
    未判定 --> 却下済 : タグ不要にした

    承認済 --> [*]
    却下済 --> [*]

    note right of 未判定
        ここにいる間だけ画面に出る
        再解析で上書きされる(派生データ)
    end note

    note right of 却下済
        再生成できない
        reset でも消えない
    end note
```

**「未判定」へ戻る遷移はありません。** 取り消す手段を用意していないのは、
このツールの中心にある「却下したものが復活しない」と両立しないためです。

### 状態の判定のしかた

状態は列で持たず、表の有無で決まります。

| 状態 | 条件 |
| --- | --- |
| 未判定 | `SUGGESTION` にあり、`VERDICT` にも `RECORD_VERDICT` にも無い |
| 承認済 | `VERDICT.DECISION = 'approved'` |
| 却下済 | `VERDICT.DECISION = 'rejected'` |

`ListPending` はこの条件をそのまま SQL にしたものです。

### 再解析したときの振る舞い

```mermaid
stateDiagram-v2
    state "解析が同じ提案を作る" as again
    [*] --> again

    again --> 保存する : 判定が無い
    again --> 保存しない : すでに判定がある
    again --> 保存しない : その記録が「タグ不要」

    保存する --> [*] : stored = true
    保存しない --> [*] : stored = false<br/>(SkippedByVerdict に数える)
```

識別子が `(記録ID, タグ名)` から決まるので、**同じ組み合わせは必ず同じ行**になります。
何度解析しても重複しません。

## 2. 記録の状態

記録は gkill にあるもので、こちらは「その記録をどう扱ったか」だけを持ちます。

```mermaid
stateDiagram-v2
    [*] --> 対象外 : gkill に記録が生まれる

    対象外 --> 判定待ち : 期間内 かつ タグ無し<br/>かつ 未評価 かつ 未判定
    判定待ち --> 評価済 : 判定した(提案0個でも)

    評価済 --> 提案あり : 閾値を超えた提案がある
    評価済 --> 提案なし : 提案が0個

    提案あり --> 確定済 : 人が確定した
    提案なし --> [*] : 何も起きない

    確定済 --> [*]

    note right of 提案なし
        失敗ではない
        「タグを付けない」という正常な答え
    end note

    note left of 対象外
        タグが付いている記録は既定で対象外
        (exclude.already_tagged)
    end note
```

### 「対象外」になる条件

| 条件 | 設定 |
| --- | --- |
| 期間の外 | `scope.candidate_days` |
| タグが1つでも付いている | `exclude.already_tagged`（既定 真） |
| 種別が対象外 | `scope.data_types`（空なら全種別） |
| リポジトリが対象外 | `scope.rep_prefixes`（空なら全リポジトリ） |
| すでに人が判定した | `VERDICT` / `RECORD_VERDICT` にある |
| すでに評価した | `EVALUATION` にある |

**「評価済」は派生データです。** `reset` で消えるので、設定を変えたあとは判定し直せます。
一方で人の判定は残るので、却下したものは復活しません。

### タグ不要にした記録

```mermaid
stateDiagram-v2
    [*] --> タグ不要 : 何も選ばずに確定

    タグ不要 --> タグ不要 : 再解析<br/>(新しいタグの提案も出ない)

    note right of タグ不要
        RECORD_VERDICT に入る
        戻す手段は用意していない
    end note
```

記録の一定割合は元々タグが要りません。実データでは、ある種類の記録の
約4分の1がそれに当たりました。覚えておかないと毎回蒸し返すことになります。

## 3. セッションの状態

2種類あります。**gkill を叩くためのもの**と、**確認画面のログイン状態**です。

### 3.1 gkill を叩くセッション

```mermaid
stateDiagram-v2
    [*] --> 未発行 : 起動

    未発行 --> 有効 : account_state.db へ書く<br/>(パスワードは要らない)

    有効 --> 有効 : 期限まで10分より長い
    有効 --> 取り直し : 期限まで10分を切った
    有効 --> 取り直し : gkill が認証エラーを返した

    取り直し --> 有効 : 新しい行を書き、古い行を消す

    有効 --> [*] : 終了時に消す

    note right of 取り直し
        新しいものを取れてから古いものを消す
        逆にすると、発行に失敗したとき
        手元のセッションまで失う
    end note
```

有効期間は **1週間**、取り直しは期限の **1時間前**からです。
gkill のサブコマンドは5分ですが、確認画面は何日も上がったままになるので足りません。

長い期限は、gkill の `account_state.db` に長寿命の鍵を置くということです。
終了時には必ず消しますが、強制終了させられると期限まで残ります。
それでも危険が増えないのは、この鍵で読める先が
「同じ端末の設定ディレクトリに書ける人」の記録だけであるためです。

**gkill の `/api/login` は一度も叩きません。** そのため gkill 側のログイン回数を消費しません。

### 3.2 確認画面のログイン状態

```mermaid
stateDiagram-v2
    [*] --> 未ログイン

    未ログイン --> 未ログイン : 資格情報が違う(401)
    未ログイン --> 制限中 : 15分に5回を超えた

    制限中 --> 制限中 : 正しい資格情報でも通さない
    制限中 --> 未ログイン : 15分が経つ

    未ログイン --> ログイン中 : 照合が通る

    ログイン中 --> 未ログイン : ログアウト
    ログイン中 --> 未ログイン : 1週間経過
    ログイン中 --> 未ログイン : サーバを再起動<br/>(状態はメモリにしか無い)

    note right of 制限中
        照合は手元の account.db に対して行う
        gkill 側の回数は減らないので
        gkill には入れる
    end note
```

ログイン状態は**メモリにしか持ちません**。再起動すると全員入り直しになりますが、
確認画面は自分で建てて自分で使うものなので、それでよいと判断しました。

### 3.3 ログインした利用者の見え方

```mermaid
stateDiagram-v2
    [*] --> ログイン中

    ログイン中 --> 解析対象 : --user に渡されている
    ログイン中 --> 対象外 : --user に渡されていない

    解析対象 --> [*] : 自分の提案が見える<br/>承認・解析ができる
    対象外 --> [*] : 提案は空<br/>承認・解析は 403

    note right of 対象外
        画面は「対象に含まれていません」と出す
        「提案が0件」と取り違えないため
    end note
```

## 4. 解析の状態

利用者ごとに1つだけ走ります。

```mermaid
stateDiagram-v2
    [*] --> 待機

    待機 --> 実行中 : /api/analyze または --once
    実行中 --> 待機 : 完了(結果を残す)
    実行中 --> 待機 : 落ちた(理由を残す)

    実行中 --> 実行中 : 同じ利用者が再度要求<br/>(いまの進み具合を返すだけ)
    実行中 --> 実行中 : 1件の判定に失敗<br/>(飛ばして次へ)

    note right of 実行中
        別の利用者の解析は止めない
        利用者ごとに数えている
        要求が切れても止まらない
    end note
```

**実行中は要求の寿命と無関係です。** 画面は `GET /api/analyze/status` を
覗きに来るだけなので、タブを閉じても解析は続きます。止まるのは Ctrl+C のときだけです。

**1件の判定に失敗しても実行中のままです。** その記録を飛ばして次へ進み、
件数だけを `FailedRecords` に数えます。飛ばした記録は評価済みにしないので、
次の解析でやり直されます。落ちるのは、保存先に書けないなど解析そのものが
続けられない場合だけです。
