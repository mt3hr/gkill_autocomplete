# gkill_autocomplete

[gkill](https://github.com/mt3hr/gkill) に溜まった記録に、**付けるべきタグを提案する**ツールです。

提案するだけで、**自分では書き込みません**。付けるかどうかは、専用の確認画面で人が1件ずつ決めます。

## これはなに？

gkill には写真・メモ・金銭記録などが日々溜まります。その多くは後から手作業でタグを付けることになりますが、
同じような記録に同じようなタグを付ける作業が延々と続きます。

gkill_autocomplete は、**過去に自分が付けたタグを見て学習し**、まだタグが付いていない記録に対して
「これはこのタグでは？」を提案します。判定にはローカルの LLM を使うので、
記録が外部のサービスへ送られることはありません。

### 3つの原則

**1. 書き込まない。** 提案するだけです。タグを付けるのは人が確認画面で承認したときだけで、
勝手にタグが増えることはありません。

**2. 0個も正しい答え。** すべての記録にタグが必要なわけではありません。
「タグ不要」も提案結果のひとつとして扱い、確認画面で却下した記録は二度と提案しません。

**3. 外に出さない。** LLM の接続先がループバック以外だと**起動を拒否します**。
クラウド LLM の設定項目そのものを用意していません。

## 必要なもの

- 稼働中の gkill サーバ（**同じ端末で動いていること**）
- ローカルの LLM サーバ（OpenAI 互換の `/v1/chat/completions` を持つもの。Ollama / llama.cpp / LM Studio など）
  - 本文の判定に使うテキストモデル
  - 写真の判定に使う視覚モデル
- Go 1.26.4 以上、Node.js 20.19 以上（ビルドする場合）

## インストール

```
npm i
npm run install_app
```

## 使い方

### 0. パスワードは要りません

渡すのは gkill の利用者IDだけです。

```
gkill_autocomplete --user <利用者ID>
```

gkill を叩くためのセッションは `$GKILL_HOME/configs/account_state.db` へ直接書いて
発行します。gkill 自身の `auto_tag` や `update_cache` と同じ手口で、
**信頼の根拠は「gkill と同じ端末で設定ディレクトリに書けること」**です。

そのため定期実行に登録しても、秘密を置く必要がありません。

`--user` は繰り返せます。指定した人ぶんだけ解析が回り、保存先も人ごとに分かれます。

### 1. 設定を作る

```
gkill_autocomplete init --user <利用者ID>
```

稼働中の gkill を解析して、`$GKILL_AUTOCOMPLETE_HOME/config.json`（既定 `$HOME/gkill_autocomplete/config.json`）を作ります。
既存の設定は上書きしません。

**LLM に問い合わせて、使えるモデルも書き込みます。** 名前から「写真を扱えそうなもの」と
「本文向きのもの」を選び、選んだ結果を画面に出すので、違っていれば設定を直してください。
LLM が動いていなくても `init` は失敗しません（モデルの欄が空になるだけです）。

設定できる項目は [config.example.json](config.example.json) を参照してください。
`gkill_autocomplete --print-config` で既定値をそのまま出力できます。

### 2. 解析する

```
gkill_autocomplete --user <利用者ID> --once
```

まだタグが付いていない記録を調べて、提案を作ります。定期実行したい場合はこれをタスクスケジューラ等に登録します。

### 3. 確認する

```
gkill_autocomplete --user <利用者ID>
```

Web サーバが起動するので、ブラウザで開いて1件ずつ承認・却下します。
**gkill のアカウントでログインします。有効なアカウントなら誰でも入れますが、
見えるのは自分の提案だけです。**

通信は gkill 本体と同じ証明書で暗号化されます。
別の端末から開く場合は、その証明書がどの名前を保証しているかを確かめてください
（[運用の手引き](documents/reverse/operations-guide.md)の3章）。

画面は PWA なので、ホーム画面に入れて単体のアプリのように開けます。
**Service Worker が溜めるのは画面の器だけで、記録の中身は決してキャッシュしません。**

画面はキーボードだけで捌けます。

| キー | 動作 |
| --- | --- |
| `j` / `k` | 次／前へ |
| `1`〜`9` | 候補タグを選ぶ（複数選べます） |
| `Enter` | 選んだタグで確定（**何も選ばずに確定＝タグ不要**） |
| `x` | タグ不要として却下 |

### 4. 精度を確かめる（任意）

```
gkill_autocomplete benchmark --user <利用者ID> --from 2020-06-01 --to 2020-06-08
```

既にタグを付け終えた過去の期間を使って、提案がどれくらい当たるかを測ります。
学習には計測期間より前の記録だけを使うので、自分の答えを見て当てることはありません。
**保存先にも gkill にも一切書き込みません。**

閾値を調整するときは、これを見ながら決めてください。

## 個人情報の扱い

このツールは生活の記録そのものを扱うので、以下を設計上の制約としています。

- **LLM はローカル限定**。ループバック以外の接続先は起動時に拒否します
- **通信先は gkill とローカル LLM の2つだけ**。テレメトリも更新チェックもありません
- **確認画面は認証と TLS の後ろ**。記録に触れる口は1つ残らずログインを要ります
- **資格情報を保存するファイルがありません**。パスワードもハッシュもセッションも持ちません
- **Service Worker に記録を溜めさせません**。`/api` と `/thumb` は素通しです
- **利用者ごとに完全に分けます**。他人の提案は1件も見えません
- **ログに本文・ファイル名・資格情報を出しません**
- **リポジトリに個人データを置きません**。設定・データベース・ログはすべてリポジトリの外に作られます

## gkill 本体との関係

gkill には**一切変更を加えません**。ただし認証まわりだけは
gkill のコード（`github.com/mt3hr/gkill/src/server`）を import して使います。
パスワードの照合を自前で書き直すと、Argon2id のパラメータや比較の仕方がずれたときに
**静かに弱くなる**種類の間違いになるためです。

起動時に `account.db` のスキーマ版を確かめ、現行版でなければ何もせずに止まります。
旧版を開くと gkill 側が自動移行を走らせ、**全アカウントのパスワードが無効化される**ためです。
